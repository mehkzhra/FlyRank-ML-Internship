Which content pages should be reviewed first?

An honest, public-safe comparison of a transparent rule and three classifiers for prioritizing scarce editorial review time.

Mehak Zahra · 5 September 2026 · Client-group holdout · Human-in-the-loop decision support

Abstract

This study asks which measurable FlyRank content pages an editor should review first when review capacity is limited. I analyzed a public-safe 30,000-page internship slice and used the supplied 30-day comparison to define an observed-decline proxy. I compared a frozen low-CTR visibility rule with Logistic Regression and Random Forest on the same 6,163-page holdout containing seven entirely unseen client groups. The simple rule achieved Precision@50 of 0.78, compared with 0.74 for Logistic Regression and 0.60 for Random Forest; the negative modeling result kept the transparent rule as the operational queue. The output is a human-reviewed FlyRank content triage playbook, not a forecast of Google's algorithm or evidence that refreshing a page causes recovery.

Introduction / problem statement

FlyRank content teams can have thousands of measurable pages but limited editorial review time. The real decision is not “which page will certainly recover?” but “which pages should an editor inspect first, and what evidence-based review route fits each one?” One row represents one anonymized content page; the output is a ranked queue with reason codes for metadata review, refresh review, content expansion, engagement review, protection, or monitoring.

A false positive consumes scarce editor time and may trigger an unnecessary change to a strong page. A false negative can leave a meaningful opportunity unreviewed. Precision@50 matches a practical first batch of 50 reviews, while grouped validation asks whether the ranking transfers to client patterns not seen during development.

Intended useA FlyRank content editor or SEO analyst privately checks page, query, SERP, analytics, seasonality, and business context before accepting or rejecting a route. Nothing is automatically published, deleted, redirected, pruned, or promised to recover.

Data

The analysis uses content_refresh_anonymized.csv, the bundled public-safe starter release: 30,000 rows × 44 fields at one-row-per-content-page grain. Its measures include trailing 90-day search and engagement aggregates and two adjacent 30-day comparison windows.

Repository documentation connects this slice to release flyrank_pseudonymized_warehouse_release_v20260703, exported 3 July 2026. The full warehouse contains 78,835,655 daily content-performance rows spanning 27 January 2025 through 30 June 2026.

Scope boundaryThis experiment did not query the full fact table and is not a 79-million-row benchmark. It analyzes the 30,000-page starter slice. The larger release is credited and documented only as the data ecosystem from which the internship materials derive.

The full sample contains 16,262 proxy-positive pages (54.21%). The grouped test set contains 6,163 pages across seven entirely unseen client groups, with a 51.10% positive base rate.

Public-safety exclusions

No raw client names, domains, URLs, titles, keywords, or queries are used or displayed. Pseudonymous IDs support grouping only. Direct label fields and components—trend_direction, trend_pct, and the last/previous 30-day impression, click, and session fields—are excluded from the feature matrix.

Methodology

Label and assumption

The binary proxy is positive when supplied trend_direction is down: last-30-day impressions are more than 20% below the preceding 30 days. It describes observed current-window decline, not a future outcome or refresh success.

Features

The learned models use 17 numeric and eight categorical source fields covering safe search-market context, content depth, trailing activity, active-day counts, age, update recency, CTR, average position, engagement, scroll, AI-traffic rate, and transparent tiers. Numeric missing values use median imputation plus missingness indicators; categories use most-frequent imputation and one-hot encoding.

Baseline and models

The frozen baseline multiplies visibility percentile, position-1-to-20 opportunity, a CTR gap below 0.50%, and a 100-impression eligibility gate. Logistic Regression is the readable learned comparison; a constrained 250-tree Random Forest tests whether non-linear complexity earns its place. Seed 42 is fixed, and Precision@50 is the primary metric.

Validation and leakage checks

The split holds out 20% of client groups: 25 clients (23,837 rows) for training and seven clients (6,163 rows) for testing, with no client overlap. Baseline and models are evaluated on exactly those test rows. A deliberate trend_pct leak drove grouped ROC AUC to 0.999; it was removed before reporting the honest result.

Residual timing riskTrailing-90-day aggregate features overlap the two 30-day periods defining the proxy. They do not directly encode the answer, but the overlap prevents a clean future-prediction interpretation. The valid framing is contemporaneous triage.

Results

The frozen rule placed 39 observed-decline pages in its first 50, compared with 37 for Logistic Regression and 30 for Random Forest. The primary result is therefore negative for added complexity: the readable rule remained the Precision@50 winner.

Logistic Regression improved Precision@10 from 0.70 to 0.80, and Random Forest had the strongest overall ROC AUC at 0.612. Neither result overrides the chosen operational metric. The action playbook therefore uses the frozen rule for ordering and keeps all routes behind human review.

Limitations & honest framing

  1. The study uses a 30,000-page slice, not the 78.8M-row daily fact table; representativeness is unproven.
  2. The target is a contemporaneous operational proxy—not future performance or refresh success.
  3. Trailing-90-day features overlap the proxy windows, preventing a leakage-clean forecast claim.
  4. Model selection and reporting share one grouped holdout; this can make the result optimistic.
  5. The client panel is unbalanced, and zeros can mix no activity with unavailable tracking.
  6. Feature importance describes fitted-model behavior, not why a page declined.
  7. No causal claim is made. A prospective experiment is required to test whether acting improves outcomes.

Ranked recommendations

  1. Review high-confidence, high-exposure candidates first. Begin with 50; verify the decline and editorial context before changing content.
  2. Route by reason code. Inspect snippet/intent fit for visible low-CTR pages, coverage for thin pages, and experience/content fit for low-engagement pages.
  3. Keep a human approval gate. Never auto-publish, prune, redirect, or promise recovery from this score.
  4. Capture review outcomes. Record accepted/rejected recommendations, action, review cost, and later outcomes to build an intervention-aware label.
  5. Upgrade validation before production. Use non-overlapping historical features and future targets, then reserve an untouched time-and-client confirmation set.
